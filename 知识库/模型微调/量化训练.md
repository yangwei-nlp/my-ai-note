# 量化训练 (Quantized Training)

## 简介

量化训练是指在低精度数值表示下进行模型训练或微调的技术，主要用于减少显存占用和加速推理。在模型微调领域，量化技术常与参数高效微调方法结合使用。

## 量化类型对比

| 类型 | 全称 | 特点 | 应用 |
|------|------|------|------|
| **QAT** | Quantization-Aware Training | 训练中感知量化影响 | 追求极致性能 |
| **PTQ** | Post-Training Quantization | 训练后量化 | 快速部署 |
| **GPTQ** | General-purpose Post-Training Quantization | 针对生成模型的 PTQ | 大模型量化 |
| **AWQ** | Activation-aware Weight Quantization | 考虑激活分布 | 4-bit 高精度 |

## 精度格式

### 常见数据类型

```
FP32 (32位浮点) → 基准精度
FP16/BF16 (16位浮点) → 混合精度训练
INT8 (8位整型) → 推理加速
INT4/NF4 (4位整型) → 极致压缩
```

### NF4 (Normal Float 4)

QLoRA 中使用的特殊 4-bit 格式：
- 基于正态分布的最优量化分位点
- 比均匀量化的 INT4 精度更高
- 典型配置：NF4 + 双重量化

## QAT 量化感知训练

### 原理

在正向传播中模拟量化效果，反向传播时使用 STE (Straight-Through Estimator) 传递梯度：

```
正向:  w_q = round(w / scale) * scale
反向:  ∂L/∂w = ∂L/∂w_q  (STE)
```

### 训练流程

```
1. 插入 FakeQuant 算子
2. 收集激活统计信息（Calibration）
3. 量化感知训练
4. 导出量化模型
```

## GPTQ 训练后量化

### 原理

- 逐层量化，最小化输出误差
- 使用 OBS (Optimal Brain Surgeon) 方法补偿量化误差
- 支持 2/3/4/8 bit 量化

### 使用示例

```python
from auto_gptq import AutoGPTQForCausalLM, BaseQuantizeConfig

quantize_config = BaseQuantizeConfig(
    bits=4,                    # 4-bit 量化
    group_size=128,            # 分组大小
    desc_act=False,            # 激活降序排序
)

model = AutoGPTQForCausalLM.from_pretrained(
    model_id,
    quantize_config
)

# 量化
model.quantize(examples)  # 使用校准数据
model.save_quantized(quantized_path)
```

## AWQ 激活感知的权重量化

### 特点

- 保护激活值重要的权重通道（Salient Channels）
- 相比 GPTQ 损失更小
- 推理速度更快

### 使用示例

```python
from awq import AutoAWQForCausalLM

model = AutoAWQForCausalLM.from_quantized(
    quant_path,
    fuse_layers=True,  # 融合层以加速
)
```

## BitsAndBytes 量化

### 配置

```python
from transformers import BitsAndBytesConfig

bnb_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",           # NF4 或 FP4
    bnb_4bit_compute_dtype=torch.bfloat16,
    bnb_4bit_use_double_quant=True,      # 双重量化
)

model = AutoModelForCausalLM.from_pretrained(
    model_id,
    quantization_config=bnb_config,
    device_map="auto",
)
```

## QLoRA 详解

QLoRA = Quantized Model + LoRA

### 内存优化

| 配置 | 显存占用 (65B模型) |
|------|-------------------|
| FP16 全量 | ~130 GB |
| INT8 | ~65 GB |
| QLoRA (4-bit) | ~35 GB |

### 双重量化

```
第一层：权重 → 4-bit (NF4)
第二层：量化常数 → 8-bit
```

## 量化与微调的整合

### 不同方法的显存需求

| 方法 | 显存占用 | 适用场景 |
|------|----------|----------|
| 全量微调 (FP16) | 100% | 充足资源 |
| LoRA (FP16) | ~30% | 常规微调 |
| QLoRA (NF4) | ~15% | 消费级显卡 |
| 8-bit + LoRA | ~20% | 质量优先 |

### 推荐配置

```python
# 消费级显卡 (24GB)
qlora_config = LoraConfig(
    r=64,
    lora_alpha=16,
    target_modules=["q_proj", "v_proj", "k_proj", "o_proj"],
)

bnb_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",
    bnb_4bit_compute_dtype=torch.bfloat16,
    bnb_4bit_use_double_quant=True,
)
```

## 精度对比

| 量化方法 | 平均精度损失 | 推理加速 |
|----------|-------------|----------|
| FP16 基线 | 0% | 1x |
| 8-bit | <1% | 1.5-2x |
| GPTQ-4bit | 2-4% | 3-4x |
| AWQ-4bit | 1-2% | 3-4x |
| QLoRA | 2-5% | 微调场景 |

## 实践建议

1. **优先使用 QLoRA**：显存效率高，质量可接受
2. **重要任务用 8-bit**：精度敏感场景
3. **推理用 AWQ/GPTQ**：平衡速度与精度
4. **避免 INT2**：损失过大，效果差
